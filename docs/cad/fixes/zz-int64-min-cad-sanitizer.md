# ZZ：最小有符号整数的精确幅值

## 表示边界

`INT64_MIN` 的正幅值不属于 `int64_t` 的表示范围。需要幅值的路径不能先在有符号类型中取负再转无符号，否则在转换前已产生未定义行为。

## 实现契约

按无符号模算术计算 `uint64_t(0) - uint64_t(v)`，得到负数 v 的精确幅值，包括 `INT64_MIN`。`gcd` 和 `sizeinbase` 在有符号取负前识别最小值。该处理用于 `ZZ.hh` 中涉及小整数幅值的加减、复合赋值及余数等路径。

这是对可信基线算术边界的局部修改；QQ 继续使用现有 ZZ 分子分母表示。

## 回归与审查

`test_number.cc` 使用明确的十进制期望值检查本项修改。加法分别覆盖大小整数的两个操作数顺序及小整数溢出回退；减法覆盖大整数减最小值及小整数结果越界。复合赋值、gcd、位数与余数的边界断言放在各自的接口测试中。

```sh
make test/test_number
_build/debug/bin/test_number
```

验证：项目默认编译器构建并运行 `test_number`，345 项断言通过。

sanitizer 检查应开启错误即停止选项。当前环境的 GCC sanitizer 链接缺少 `asan` 库，Clang 构建受总头文件中 `variable.hh` / `realroot.hh` 的兼容问题阻碍，因此合并后的测试不声明已通过 sanitizer；这不影响默认编译器的上述回归结果。
